# gpla67.ini at 144 Hz -- every AI value, grouped by unit

Generated by `tools/gplaiscale.py --markdown` from the same tables that rescale the file, so it
matches what the script writes. Do not edit by hand; regenerate it.

GPL's AI reads its tunables from this ini, and most time-valued keys are in **ticks**, not
seconds. A value is rescaled as `new = old x (144 / 36)^k`, where `k` is the key's unit
exponent. `k` is read off a known-good pair -- gpl_ai.ini.98 (36 Hz) against gpl_ai_60fps.ini (60 Hz,
rescaled by hand by the 60 fps patch authors) -- and then corrected where that pair
contradicts the units the AI code actually uses (see Corrections). The unit column is the
ini's own trailing comment, where it has one.

## Corrections: where the reference pair is overruled

Each was checked against the code that consumes the value. The longer working is in the
comments on `OVERRIDES` and `KEY_OVERRIDES` in `tools/gplaiscale.py`.

- **[GP] nominal_max_accel** -> rate^-2: meters/tick^2; the comment gives 1G = 0.007562 = 9.80665/36^2
- **[GP] nominal_traction_circle** -> rate^-2: meters/tick^2; 0.011154 = 1.474 * ONE_G, as its own comment says
- **[physics] gear_shift_rpm_decrement** -> rate^-1: RPM per tick, a rate of change; the shift's length scales rate^+1
- **[physics] max_lat_acc_from_speed** -> rate^-1: value * speed(m/tick) = accel(m/tick^2), so the value is 1/tick. Proved by rate-invariance: only rate^-1 reproduces stock's 3.95 G at every rate
- **[physics] yaw_accel_k1** -> rate^-2: spring gain of the per-tick yaw integrator sub_4982F0, 1/tick^2
